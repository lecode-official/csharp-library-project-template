# Changelog

All notable changes to the C# library project template are documented here, newest release first. Each release corresponds to an annotated Git tag of the same name.

## Release v1.2.0

*Release date to be determined.*

- Raised the minimum Copier version from 9.6.0 to 9.10.3. Before 9.10.3, an update from v1.0.0 deleted every file the template only creates, such as the read me, the changelog, and the logo, instead of leaving them alone. The continuous integration now renders and updates once with the minimum version, which it reads from `copier.yml`.
- Added an optional branch protection script to the GitHub setup of the template repository and of the generated project. It protects the default and the integration branch with two rulesets: no force pushes and no deletion for anyone, and, with a bypass for administrators, changes only through a pull request with passing checks. A new `Pull Requests` workflow fails a pull request into the default branch that does not come from the integration branch, so that a Dependabot security update opened against the default branch can no longer be merged there. The `Linters` and `Tests` workflows now run on every pull request and on every push to the default and the integration branch, instead of on every push, since a job they skipped would count as a passed check.
- Added issue forms for a bug report and a feature request, and a pull request template, to the template repository and to the generated project. The forms ask for the sections the GitHub workflow article describes and preset the `Type: Bug` or the `Type: Idea or Request` label, a blank issue stays available, and a security vulnerability is pointed at the security policy. The pull request template asks for what changed and why, the disclosure of any AI involvement, and the issue it resolves.
- Added a `Dependabot Security Updates` workflow to the template repository and to the generated project. Dependabot applies its configuration only to version updates, so it opens a security update against the default branch and without a label; the workflow now points such a pull request at the integration branch and gives it the `Dependabot:` label of its ecosystem as soon as it is opened. It runs on `pull_request_target`, never checks out the pull request's code, and takes effect once it has reached the default branch. An existing project gets it with `copier update`.
- Added questions for the name, the directory, and the root namespace of the generated project's sample app, `sample_app_name`, `sample_app_slug`, and `sample_app_namespace`, whose defaults are the names it had so far, and gave `root_namespace` a default derived from `library_slug`, so that `cli-net-core` becomes `CliNetCore`. The library slug may no longer be `unit-tests` or `documentation-website`, which name other directories under `build/`, but may now be `sample-app` if the sample app's slug differs. An update with `--defaults` changes nothing, and an update that renames the sample app leaves `Program.cs` and the sample app's `README.md` behind, to be moved into the new directory by hand.
- Named the two instructions that start and finish the work on an issue in the Git workflow articles and the `AGENTS.md` files of the template repository and of the generated project. "Start the next issue" lets an assistant pick the next issue, skipping and reporting any that is assigned to someone else, assign it, create and check out its linked branch, implement it, and write the commit message, and "finish the issue" lets it commit, push, open the pull request, assign it to the user, merge it once its checks pass, close the issue, and delete the branch. A new section of the GitHub workflow articles on planning a release says that the milestone and the release issue are created at the start of a release, and that the release issue lists the order of the other issues as a numbered list, whose items are worked through from top to bottom and whose issues within one item can be worked on at the same time.
- Added link checking to the MarkdownLint configurations of the template repository and of the generated project, with the `relative-links` rule of the npm package `markdownlint-rule-relative-links`, which `.markdownlint-cli2.yaml` loads. `npm run lint` now fails on a relative link to a file that does not exist, and on a link to a heading of another file that does not exist; external links are not checked. An existing project gets the rule with `copier update`, runs `npm install`, and fixes the broken links the linters report.
- Added a job to the continuous integration of the template repository that renders the last release, updates it to the current commit with `copier update`, and fails on conflicts, on changes to the files the template only creates, and on a project that no longer passes its linters, tests, and packaging. Split the `Template` workflow into a `Linters` and a `Tests` workflow, like the generated project's.

## Release v1.1.0

*Released on November 5, 2026.*

- Raised the dependencies to their newest releases: the default .NET SDK to 10.0.403, and the serviced 10.0.1xx band named in its help to 10.0.114, both of which carry the security fixes of .NET 10.0.14; dprint to 0.64.3 and its Markdown plugin to 0.28.2; Nullable.Extended.Analyzer to 1.19.0; ReportGenerator to 5.5.12; Material for MkDocs to 9.8.0; and the `actions/setup-dotnet` and `actions/setup-python` actions to 6.1.0 and 7.1.0, in the template repository and in the generated project. An existing project gets all of them with `copier update`, except the SDK, whose version is an answer: it raises it with `copier update --defaults --data dotnet_sdk_version=10.0.403`, or to the newest patch of the band it uses, and then brings its lock files up to date.
- Excluded the files every project fills with its own content from every update: the read mes, the changelog, the list of contributors, the sample app, the index and the getting started article of the User Manual, and now also the logo files, the brand colors, and the logo design article. `copier update` neither overwrites them nor creates them again once a project has deleted them, which `_skip_if_exists` did before. The template now needs Copier 9.6.0 or newer.
- Fixed the alignment of the logo in the title of the generated read me, which sat above the title text, and slimmed down the read me's developer setup to the requirements and a link to the new development setup section, dropping its Visual Studio Code section. An existing project keeps its read me on `copier update`, so it replaces the title line and the "Developer Setup" section, and removes the "Visual Studio Code Integration" section, by hand. A project that still uses the placeholder logo also copies `docs/assets/images/header-logo-dark.svg` and `header-logo-light.svg` from a fresh render, since the new title line expects them cropped.
- Labeled the pull requests of Dependabot with a `Dependabot:` label per ecosystem, instead of the labels Dependabot creates itself, and pointed Dependabot at the integration branch with `target-branch`, so that its pull requests no longer go into the default branch. Dependabot never creates a label, so an existing project creates the new labels, together with the new `Type: Release` label, with the label script of its development setup, deletes the `dependencies` label and the ecosystem labels Dependabot created, and relabels the Dependabot pull requests that are still open.
- Added messages that Copier shows after generating and after updating a project. The message after generating lists what has to happen before the first commit and points to a new first steps article in the generated project, which covers everything else to do once. The message after updating lists the steps every update needs and a hint for every release that changed something to carry over by hand, and points to a new migration guide in the template repository. Neither needs `--trust`.
- Added a development setup section to the documentation of the template repository and of the generated project. It moves the developer setup articles there as "Installing the Tools", which now also cover Git and the optional GitHub CLI, and adds articles on setting up Visual Studio Code and on setting up GitHub, with scripts for the labels, the repository settings, and, in the generated project, GitHub Pages.
- Rewrote the Git workflow articles of the template repository and of the generated project to cover the branches, the `feature/`, `fix/`, and `release/` branch names, rebasing a branch to bring it up to date, deleting merged branches, fast-forwarding the integration branch after a release, and tags, including that a release tag points at the merge commit that brought the release into the default branch.
- Added an article on the GitHub workflow to the conventions of the template repository and of the generated project, covering issues, issue and pull request titles, labels, milestones, pull requests, Dependabot pull requests, and the release process with its release issue, release branch, and two pull requests, and creating the GitHub Release from an existing annotated tag.
- Moved the changelog conventions out of the versioning articles into an article of their own, and added the rule that Markdown files contain no comments, in the conventions of the template repository and of the generated project.
- Moved the settings that turn off Pylint and Flake8 into the shared Visual Studio Code settings of the template repository and of the generated project.

## Release v1.0.0

*Released on October 23, 2026.*

- Added the tooling of the template repository itself: formatting with dprint, Markdown linting with MarkdownLint, spell checking with CSpell, the Visual Studio Code integration, and the Claude Code hooks.
- Added the conventions of the template repository, its `AGENTS.md`, and its community files.
- Added the Copier template: the core questions with their validators, and the split between the template repository and the template body in `template/`.
- Added the `license` question, with ten vendored license texts and the script that refreshes them.
- Added the documentation of the generated project: its read me, `AGENTS.md`, community files, changelog, and the developer and user manuals.
- Added the C# solution of the generated project: the library, the sample app, and the pinned .NET SDK.
- Added the NuGet packaging of the library: package metadata, inherited documentation comments, package validation, and a symbol package.
- Added the unit test project of the generated project, based on xUnit v3 and Microsoft.Testing.Platform, with code coverage.
- Added Central Package Management, lock files, and the NuGet vulnerability audit to the generated project.
- Added formatting with dprint, Markdown linting with MarkdownLint, and spell checking with CSpell to the generated project.
- Added strict static code analysis to the generated project, with the .NET analyzers, StyleCop Analyzers, Roslynator, and Nullable.Extended.
- Added the documentation website of the generated project, built with ProperDocs, including a generated API reference.
- Added the continuous integration workflows and the Dependabot configuration of the generated project.
- Added the Visual Studio Code integration of the generated project.
- Added the Claude Code integration of the generated project.
- Added a placeholder logo to the generated project, used in its read me, its documentation website, its favicon, and its package icon.
- Added the continuous integration of the template repository, which renders the template with every license and both serviced SDK bands.
